# Codebase Concerns

**Analysis Date:** 2026-08-07

## Tech Debt

**Demo behavior is embedded directly in production UI paths:**
- Issue: Search, notebook answers, advisor recommendations, council replies, source content, and artifact generation are deterministic client-side rules over 22 hard-coded cards. Artificial delays present these synchronous rules as AI processing. Files: `src/data/mockCards.ts`, `src/lib/search.ts`, `src/lib/sources.ts`, `src/data/advisor.ts`, `src/data/council.ts`, `src/components/notebook/NotebookChat.tsx`, `src/components/notebook/StudioPanel.tsx`, `src/components/advisor/AdvisorFlow.tsx`, `src/components/Footer.tsx`.
- Impact: The product cannot ingest new knowledge, retrieve authoritative content, call a model, or provide evidence-backed answers. UI language such as “semantic search,” “selected sources,” and “generated by AI” overstates the implemented behavior. Files: `src/routes/index.tsx`, `src/components/notebook/NotebookChat.tsx`, `src/components/notebook/StudioPanel.tsx`, `src/data/advisor.ts`.
- Fix approach: Put search, retrieval, advisor, council, source, and artifact capabilities behind typed service interfaces; implement server-backed adapters; retain the rule-based implementation only as an explicitly selected demo adapter. Files: `src/lib/search.ts`, `src/lib/sources.ts`, `src/data/advisor.ts`, `src/data/council.ts`, `src/start.ts`.

**Browser storage acts as the application database:**
- Issue: Theme, bookmarks, visibility, renamed titles, council sessions, advisor sessions, search history, notes, and feedback all persist through one unvalidated `localStorage` hook. Write and parse failures are silently ignored. Files: `src/hooks/useLocalStorage.ts`, `src/hooks/useAppState.ts`.
- Impact: Data is device-local, unavailable across browsers or users, has no audit trail, can exceed quota without warning, and can diverge from in-memory state after a failed write. Parsed values are asserted as `T` without runtime schema validation, so malformed or older data can crash consumers. Files: `src/hooks/useLocalStorage.ts`, `src/routes/council.tsx`, `src/routes/index.tsx`, `src/routes/card.$id.tsx`.
- Fix approach: Introduce a versioned repository layer with runtime schemas, migrations, surfaced persistence errors, and server storage for business data; reserve `localStorage` for low-risk preferences such as theme. Files: `src/hooks/useLocalStorage.ts`, `src/hooks/useAppState.ts`.

**Large feature modules combine state, orchestration, and presentation:**
- Issue: `src/routes/council.tsx` is 1,251 lines, `src/data/advisor.ts` is 959 lines, `src/components/notebook/StudioPanel.tsx` is 622 lines, `src/components/notebook/NotebookChat.tsx` is 537 lines, and `src/components/advisor/AdvisorFlow.tsx` is 493 lines.
- Impact: Small behavior changes touch dense modules with many implicit state transitions, making regressions and merge conflicts more likely. The largest UI paths also lack component tests. Files: `src/routes/council.tsx`, `src/data/advisor.ts`, `src/components/notebook/StudioPanel.tsx`, `src/components/notebook/NotebookChat.tsx`, `src/components/advisor/AdvisorFlow.tsx`, `vitest.config.ts`.
- Fix approach: Split each feature into a state machine/controller, pure domain functions, transport adapter, and focused view components. Keep generated artifacts and source operations in separate modules with unit-testable serializers. Files: `src/routes/council.tsx`, `src/components/notebook/StudioPanel.tsx`, `src/components/notebook/NotebookChat.tsx`, `src/components/advisor/AdvisorFlow.tsx`.

**Architecture documentation contradicts the executable repository:**
- Issue: The open-issues register names `backend/services/ingestion.py`, a `frontend/` Vanilla JS application, 25 test files, PostgreSQL/pgvector, BILife authentication, and implemented API endpoints, while the executable tree is a TanStack/React demo with no backend service, database client, or auth handler. Files: `00_docs/28_Open_Issues.md`, `00_docs/05_Архитектура_системы.md`, `00_docs/openapi.yaml`, `src/routes/index.tsx`, `src/server.ts`, `package.json`.
- Impact: Planning, security review, and operations can treat specified or historical capabilities as deployed facts. This is especially risky for access control, content licensing, tenant isolation, and AI governance. Files: `00_docs/28_Open_Issues.md`, `00_docs/11_Безопасность_и_комплаенс.md`, `00_docs/23_Threat_Model.md`, `src/hooks/useAppState.ts`.
- Fix approach: Label `00_docs/` as target architecture or align it with the executable application. Add automated checks that validate referenced paths/endpoints and generate an implementation-status matrix from the source tree. Files: `00_docs/01_Readme.md`, `00_docs/19_Трассируемость_требований.md`, `00_docs/openapi.yaml`.

**The lint gate is red:**
- Issue: `npm run lint` reports 59 errors and 9 warnings. Failures include formatting drift across core files and explicit `any` in speech-recognition code. Files: `eslint.config.js`, `src/components/BiLogo.tsx`, `src/components/SearchPanel.tsx`, `src/components/notebook/NotebookChat.tsx`, `src/data/mockCards.ts`, `src/lib/search.ts`, `src/routes/council.tsx`.
- Impact: CI cannot use the configured lint script as a merge gate, and real type-safety warnings are obscured by formatting failures. Files: `package.json`, `eslint.config.js`.
- Fix approach: Apply the configured formatter, replace speech-recognition `any` values with local Web Speech API declarations, and require `npm run lint`, `npx tsc --noEmit`, and `npm test` in CI. Files: `src/components/SearchPanel.tsx`, `src/components/notebook/NotebookChat.tsx`, `package.json`.

**Package and runtime workflows are split:**
- Issue: Both `package-lock.json` and `bun.lock` are committed; local instructions use npm, while `Dockerfile` installs and runs with Bun. The container runs the development server and `bun install` is not frozen. Files: `package-lock.json`, `bun.lock`, `README.md`, `Dockerfile`, `package.json`.
- Impact: npm and Bun can resolve different dependency graphs. Container builds are not guaranteed reproducible and do not exercise the production build artifact. Files: `Dockerfile`, `package-lock.json`, `bun.lock`.
- Fix approach: Select one package manager and lockfile, enforce frozen installs, and make the container build and serve the production output. Files: `Dockerfile`, `README.md`, `package.json`.

## Known Bugs

**Link sources are selected but absent from the source panel:**
- Symptoms: `buildNotebookSources` creates both file and link sources, and all source IDs begin selected, but `SourcesPanel` renders only `visible.filter((s) => s.kind === "file")`. Link sources contribute to counts and chat context without a visible row to inspect or deselect. Files: `src/lib/sources.ts`, `src/routes/card.$id.tsx`, `src/components/notebook/SourcesPanel.tsx`.
- Trigger: Open any card whose citations produce a link source; compare the “selected” count with the rendered “Uploaded files” rows. Files: `src/lib/sources.ts`, `src/components/notebook/SourcesPanel.tsx`.
- Workaround: A link source can only be opened indirectly when an answer citation resolves to it; there is no source-panel control. Files: `src/components/notebook/NotebookChat.tsx`, `src/components/notebook/SourcesPanel.tsx`.

**Source upload, download, rename, and delete controls imply persistence that does not exist:**
- Symptoms: File selection only shows “Files added,” dropping files discards the drop payload, source download only shows a toast, and rename/delete live only in component state. Files: `src/components/notebook/SourcesPanel.tsx`.
- Trigger: Select or drop a file, click a source download action, or reload after renaming/deleting a source. Files: `src/components/notebook/SourcesPanel.tsx`.
- Workaround: None inside the application; the controls are demo affordances. Files: `src/components/notebook/SourcesPanel.tsx`, `src/lib/sources.ts`.

**Audio and presentation downloads create invalid files:**
- Symptoms: The MP3 and PPTX actions write plain text into blobs labeled `audio/mpeg` and OpenXML presentation MIME types. The resulting `.mp3` and `.pptx` files are not valid media or Office documents. Files: `src/components/notebook/StudioPanel.tsx`.
- Trigger: Generate a podcast or deck and choose its format-specific download action. Files: `src/components/notebook/StudioPanel.tsx`.
- Workaround: Download the Markdown representation instead. Files: `src/components/notebook/StudioPanel.tsx`.

**New council sessions receive a fixed date:**
- Symptoms: Every created session uses `TODAY = "30.07.2026"`; the sidebar also uses the same constant to decide which sessions appear under “Today.” Files: `src/routes/council.tsx`.
- Trigger: Create a council session on any date other than 30 July 2026. Files: `src/routes/council.tsx`.
- Workaround: None in the UI. Replace the display constant with a date derived at creation and compare normalized calendar dates. Files: `src/routes/council.tsx`, `src/data/council.ts`.

**A delayed notebook answer can cross card boundaries:**
- Symptoms: `NotebookChat.ask` schedules an answer with `window.setTimeout` and captures the old card and citations. The card-change effect clears messages but does not cancel the pending timeout, so a callback can append an old card’s answer after the component receives a new `card.id`. Files: `src/components/notebook/NotebookChat.tsx`, `src/routes/card.$id.tsx`.
- Trigger: Submit a notebook question and navigate to another card within the 550 ms simulated thinking window. Files: `src/components/notebook/NotebookChat.tsx`.
- Workaround: Wait for the answer before changing cards. Store timer IDs and cancel them on card change/unmount, or bind each response to a request/card token. Files: `src/components/notebook/NotebookChat.tsx`.

**Malformed stored state can crash feature code or silently change persona identity:**
- Symptoms: JSON values are cast directly to generic types. Council persona lookup silently falls back to the first persona for unknown IDs, while consumers assume arrays and nested fields exist. Files: `src/hooks/useLocalStorage.ts`, `src/hooks/useAppState.ts`, `src/data/council.ts`, `src/routes/council.tsx`.
- Trigger: Load values written by an incompatible schema, browser extension, manual storage edit, or partial/corrupt write under a `biaqyl:*` key. Files: `src/hooks/useLocalStorage.ts`, `src/hooks/useAppState.ts`.
- Workaround: Clear site storage, losing all local sessions, notes, and preferences. Files: `src/hooks/useAppState.ts`.

## Security Considerations

**Internal content has no authentication or authorization boundary:**
- Risk: Routes expose “Internal BI experience,” internal business-unit filters, notes, and decision-support flows without login, session validation, RBAC, or tenant checks. `robots.txt` explicitly permits all crawlers. Files: `src/components/SearchPanel.tsx`, `src/data/mockCards.ts`, `src/routes/index.tsx`, `src/routes/card.$id.tsx`, `public/robots.txt`.
- Current mitigation: The repository contains mock data and the footer identifies demo mode; no code-level access mitigation exists. Files: `src/data/mockCards.ts`, `src/components/Footer.tsx`, `src/start.ts`.
- Recommendations: Deny indexing, require identity at the server boundary, authorize each card/source by user and business unit, and default-deny all internal routes before real content is connected. Files: `public/robots.txt`, `src/start.ts`, `src/router.tsx`, `src/routes/card.$id.tsx`.

**“Private” is only a client-side display flag:**
- Risk: Marking a card private only adds its ID to `localStorage`; the card remains present in the shipped `mockCards` bundle and can be found by direct route ID. Files: `src/hooks/useAppState.ts`, `src/routes/index.tsx`, `src/data/mockCards.ts`, `src/routes/card.$id.tsx`.
- Current mitigation: Visibility filtering hides cards in one dashboard view only. Files: `src/routes/index.tsx`, `src/components/FiltersBar.tsx`.
- Recommendations: Model privacy as server-side authorization metadata and enforce it in list, search, detail, source, and export operations. Files: `src/lib/search.ts`, `src/routes/card.$id.tsx`, `src/start.ts`.

**Business-sensitive user text persists unencrypted in browser storage:**
- Risk: Search history, management dilemmas, advisor threads, council messages, notes, feedback reports, and renamed internal titles remain readable to any script on the origin and to other users of the same browser profile. Files: `src/hooks/useAppState.ts`, `src/hooks/useLocalStorage.ts`.
- Current mitigation: No expiry, user-scoped namespace, encryption, consent control, or bulk clear operation covers these stores. Files: `src/hooks/useAppState.ts`, `src/routes/index.tsx`, `src/routes/card.$id.tsx`, `src/routes/council.tsx`.
- Recommendations: Store business data in an authenticated backend with retention rules; add explicit clear/export controls; keep only non-sensitive preferences client-side; deploy a strict CSP to reduce script-exfiltration risk. Files: `src/hooks/useAppState.ts`, `src/routes/__root.tsx`, `src/start.ts`.

**Server error recovery is global and request-unsafe:**
- Risk: A module-level `lastCapturedError` is shared across concurrent requests. `consumeLastCapturedError()` clears it, but the immediate `console.error(consumedError)` passes through the monkey-patched console and records the same error again. A later request within five seconds can therefore receive another request’s error attribution in logs. Error descriptions include stack and cause strings without redaction. Files: `src/lib/error-capture.ts`, `src/server.ts`.
- Current mitigation: Captured descriptions are truncated to 8,000 characters and never included in the HTML error page. Files: `src/lib/error-capture.ts`, `src/lib/error-page.ts`.
- Recommendations: Replace the singleton/console monkey patch with request-scoped error context, structured logging, correlation IDs, and secret/PII redaction. Ensure consuming an error cannot re-record it. Files: `src/lib/error-capture.ts`, `src/server.ts`, `src/start.ts`.

**Speech recognition lifecycle is not closed on navigation:**
- Risk: Search and notebook components retain a recognition object but provide no effect cleanup to stop it on unmount. A recognition session can outlive the visible control, and callbacks can update stale UI state. Files: `src/components/SearchPanel.tsx`, `src/components/notebook/NotebookChat.tsx`.
- Current mitigation: User action is required to start recognition, and `onend`/`onerror` clear the displayed listening flag. Files: `src/components/SearchPanel.tsx`, `src/components/notebook/NotebookChat.tsx`.
- Recommendations: Stop recognition and detach callbacks in an unmount cleanup; expose typed browser support and a persistent recording indicator. Files: `src/components/SearchPanel.tsx`, `src/components/notebook/NotebookChat.tsx`.

**Third-party font requests are unconditional:**
- Risk: Every page loads Google Fonts, disclosing client network metadata to an external service and adding an external availability dependency to a corporate knowledge interface. Files: `src/routes/__root.tsx`.
- Current mitigation: System fonts appear in fallbacks, but there is no self-hosted font path or explicit CSP. Files: `src/routes/__root.tsx`, `src/styles.css`.
- Recommendations: Self-host approved font assets and define a restrictive CSP/connect policy before handling real internal content. Files: `src/routes/__root.tsx`, `src/styles.css`, `src/start.ts`.

## Performance Bottlenecks

**Search is a full in-browser scan of the bundled corpus:**
- Problem: Every search/filter change chains multiple array filters, constructs lowercase haystacks, scores every candidate, and sorts all matches on the main thread. Files: `src/lib/search.ts`, `src/routes/index.tsx`.
- Cause: All 22 cards and their citation/framework text ship in `src/data/mockCards.ts`; there is no index, pagination query, worker, or server search. Files: `src/data/mockCards.ts`, `src/lib/search.ts`.
- Improvement path: Move retrieval to an indexed backend with server pagination and abortable requests; retain a memoized lightweight local adapter only for demo fixtures. Files: `src/lib/search.ts`, `src/routes/index.tsx`.

**Local persistence serializes growing aggregates synchronously:**
- Problem: Each council message/reaction and each note/session update clones aggregate arrays or records and synchronously serializes the full resolved value to `localStorage`. Files: `src/hooks/useLocalStorage.ts`, `src/hooks/useAppState.ts`.
- Cause: The state model stores entire conversation histories as single JSON values and has no size limits for council sessions, advisor sessions, messages, or notes. Files: `src/hooks/useAppState.ts`, `src/data/council.ts`.
- Improvement path: Persist normalized records incrementally in server storage or IndexedDB, cap retained client history, and surface quota/transaction failures. Files: `src/hooks/useLocalStorage.ts`, `src/hooks/useAppState.ts`.

**Initial-route client payload is large for a demo dashboard:**
- Problem: The production build emits an index-route client chunk around 410 kB (127 kB gzip), while shared app-state and route chunks also embed substantial data and UI code. Files: `src/routes/index.tsx`, `src/data/mockCards.ts`, `src/data/advisor.ts`, `src/hooks/useAppState.ts`, `package.json`.
- Cause: Advisor rules, all mock cards, and broad UI dependencies are imported into the dashboard path; artifacts and card workspaces also contain large in-component builders. Files: `src/routes/index.tsx`, `src/components/advisor/AdvisorFlow.tsx`, `src/components/notebook/StudioPanel.tsx`.
- Improvement path: Lazy-load advisor and artifact features, fetch card summaries separately from full content, and add bundle-size budgets to the build pipeline. Files: `src/routes/index.tsx`, `src/routes/card.$id.tsx`, `package.json`.

## Fragile Areas

**SSR error normalization:**
- Files: `src/lib/error-capture.ts`, `src/server.ts`, `src/start.ts`.
- Why fragile: Correct behavior depends on h3 emitting one exact JSON shape, on console interception ordering, and on one shared five-second error slot. Concurrent failures and framework upgrades can produce wrong diagnostics or bypass the custom error page. Files: `src/lib/error-capture.ts`, `src/server.ts`.
- Safe modification: Add request-isolation tests around simultaneous errors, preserve original response headers when normalizing, and prefer supported framework error hooks over global console replacement. Files: `src/server.ts`, `src/lib/error-capture.ts`.
- Test coverage: No tests exercise middleware, swallowed 500 bodies, concurrent requests, cause redaction, or error-page responses. Files: `vitest.config.ts`, `src/server.ts`, `src/lib/error-capture.ts`.

**Timer-driven UI state machines:**
- Files: `src/components/notebook/NotebookChat.tsx`, `src/components/notebook/StudioPanel.tsx`, `src/components/advisor/AdvisorFlow.tsx`, `src/routes/council.tsx`.
- Why fragile: Multiple raw timers control “thinking,” generation, message reveal, and transitions. Only the council reveal path centrally tracks and cancels timers; the other paths can complete after reset, card change, or unmount. Files: `src/components/notebook/NotebookChat.tsx`, `src/components/notebook/StudioPanel.tsx`, `src/components/advisor/AdvisorFlow.tsx`, `src/routes/council.tsx`.
- Safe modification: Use cancellable async operations or a reducer/state machine with request tokens; cancel all scheduled work in effect cleanup and test navigation during pending work. Files: `src/components/notebook/NotebookChat.tsx`, `src/components/notebook/StudioPanel.tsx`, `src/components/advisor/AdvisorFlow.tsx`.
- Test coverage: Vitest includes only `src/**/*.test.ts`, so TSX component timer behavior has no runnable test path. Files: `vitest.config.ts`.

**Regex-based intent and answer dispatch:**
- Files: `src/data/advisor.ts`, `src/data/council.ts`, `src/components/notebook/NotebookChat.tsx`.
- Why fragile: Keyword alternations decide dilemma type, follow-up behavior, persona reply, and notebook answer. Morphological variation, Kazakh/English input, negation, and overlapping keywords can select unrelated canned output. Files: `src/data/advisor.ts`, `src/data/council.ts`, `src/components/notebook/NotebookChat.tsx`.
- Safe modification: Keep deterministic classification as an explicit fallback, add multilingual evaluation fixtures, return confidence/unknown states, and route low-confidence requests to real retrieval/model services. Files: `src/data/advisor.test.ts`, `src/data/council.test.ts`, `src/components/notebook/NotebookChat.tsx`.
- Test coverage: Advisor and council pure functions have unit tests, but notebook intent routing, multilingual cases, negation, and end-to-end recommendation flows are untested. Files: `src/data/advisor.test.ts`, `src/data/council.test.ts`, `src/components/notebook/NotebookChat.tsx`.

**Synthetic citation and source generation:**
- Files: `src/lib/sources.ts`, `src/data/mockCards.ts`, `src/components/notebook/NotebookChat.tsx`.
- Why fragile: External/internal URLs are fabricated from a slug and chunk ID, and “source sections” repeat card summaries and metadata instead of retrieving the cited document. Footnote markers rotate across selected citations rather than mapping claims to evidence. Files: `src/lib/sources.ts`, `src/components/notebook/NotebookChat.tsx`.
- Safe modification: Store immutable source URLs and verified excerpts in backend records; attach claim-level citation IDs from retrieval output; reject missing anchors rather than manufacturing content. Files: `src/lib/sources.ts`, `src/data/mockCards.ts`, `src/components/notebook/NotebookChat.tsx`.
- Test coverage: No tests verify URL validity, citation-to-claim alignment, source visibility, or source-reader behavior. Files: `vitest.config.ts`, `src/lib/sources.ts`, `src/components/notebook/SourceReaderDialog.tsx`.

## Scaling Limits

**Knowledge corpus:**
- Current capacity: 22 static cards are compiled into the client bundle. Files: `src/data/mockCards.ts`, `src/lib/search.ts`.
- Limit: Corpus growth increases download size, memory use, and main-thread search/sort time; content updates require a rebuild and redeploy. Files: `src/data/mockCards.ts`, `src/routes/index.tsx`.
- Scaling path: Store metadata/content outside the bundle and implement indexed, access-controlled, paginated retrieval. Files: `src/lib/search.ts`, `src/routes/index.tsx`, `src/start.ts`.

**User and session data:**
- Current capacity: One browser-origin store holds all state for one browser profile; the application defines no application-level byte, session, or message cap. Files: `src/hooks/useLocalStorage.ts`, `src/hooks/useAppState.ts`.
- Limit: Browser quota and synchronous serialization bound capacity; there is no multi-device sync, concurrent editing, user isolation, backup, or recovery. Files: `src/hooks/useLocalStorage.ts`, `src/hooks/useAppState.ts`.
- Scaling path: Introduce authenticated user/tenant records, normalized conversation storage, retention limits, pagination, and migrations. Files: `src/hooks/useAppState.ts`, `src/start.ts`.

**Source and artifact processing:**
- Current capacity: No file bytes are ingested and all artifacts are generated from one in-memory card object. Files: `src/components/notebook/SourcesPanel.tsx`, `src/components/notebook/StudioPanel.tsx`, `src/lib/sources.ts`.
- Limit: The system cannot process even one uploaded document or produce a valid binary podcast/deck, regardless of source count. Files: `src/components/notebook/SourcesPanel.tsx`, `src/components/notebook/StudioPanel.tsx`.
- Scaling path: Add upload/object storage, asynchronous ingestion jobs, source status, artifact job APIs, and valid format-specific encoders. Files: `src/components/notebook/SourcesPanel.tsx`, `src/components/notebook/StudioPanel.tsx`, `src/start.ts`.
