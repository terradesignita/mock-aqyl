# Редизайн «Консилиума» — спецификация

Дата: 2026-08-02

## Проблема

Текущая реализация (`src/routes/council.tsx`, `src/data/council.ts`):

1. **Поток создания сессии медленный.** Два последовательных шага — выбрать кейс, затем вручную выбрать до 3 персон из шести — прежде чем увидеть хоть что-то по кейсу.
2. **Мнения персон визуально неразличимы.** Рендерятся одна под другой как чат-пузыри одного вида, не считывается, кто с кем согласен.
3. **Синтез не живой.** На любой уточняющий вопрос в `SessionView.send()` возвращается одна и та же заранее написанная строка — не зависит от вопроса.
4. **Персоны — шесть корпоративных ролей** (CFO, юрист, HR и т.д.) без характера.

## Решение

### 1. Создание сессии: авто-подбор персон

Выбор кейса сразу подставляет 3 персоны (детерминированная функция `suggestPersonas(topic)` в `council.ts`, без ML/LLM — например, по `businessUnit`/ключевым словам темы) и создаёт сессию без второго экрана-визарда. Состав правится после, из самой сессии, кнопкой «Изменить состав».

`NewCouncilPanel` теряет второй шаг персон; кнопка «Начать совет» активна сразу после выбора кейса.

### 2. Layout сессии: 3 колонки

```
┌──────────────┬─────────────────────┬──────────────┐
│ История +     │  Чат по кейсу        │  Вердикт      │
│ персоны       │  (реплики персон +   │  (живой,      │
│ сессии        │  уточняющие вопросы) │  открытые     │
│               │                      │  вопросы,     │
│               │                      │  согласны/    │
│               │                      │  расходятся)  │
└──────────────┴─────────────────────┴──────────────┘
```

- **Левая колонка** — существующий список «Сегодня/Ранее» + чипы персон активной сессии + кнопка «Изменить состав» (открывает picker с поиском — нужен, т.к. ростер вырос до 12).
- **Средняя колонка** — сегодняшний `SessionView`-тред (реплики персон + user follow-up), без изменений в логике взаимодействия.
- **Правая колонка** — новый «живой вердикт»: три блока входят в v1 —
  - текст синтеза (обновляется после каждого follow-up),
  - открытые вопросы (список),
  - согласны/расходятся (теги персон/утверждений).

На узких экранах колонки складываются вертикально (правая — под средней), тем же паттерном, что уже используется для `aside` на мобильных.

### 3. Персоны: 12 архетипов, стиль — по мотивам мировых лидеров

## Изменения в данных (`src/data/council.ts`)

- `CouncilPersona` получает поле `inspiredBy: string` (реальный лидер, только для bio-строки в UI).
- `COUNCIL_PERSONAS` — 12 записей по таблице выше, с уникальными `color`/`initials` (контраст ≥4.5:1 сохраняется, как в текущем комментарии).
- `suggestPersonas(topic: CouncilTopic): string[]` — детерминированный подбор 3 id персон по кейсу (без рандома/LLM).
- `buildVerdict(topic: CouncilTopic, personaIds: string[], followUps: string[]): { synthesis: string; openQuestions: string[]; agreements: { label: string; kind: "agree" | "risk" }[] }` — заменяет захардкоженную строку синтеза в `SessionView.send()`; детерминированно зависит от `topic`, состава персон и текста последнего follow-up.

## Изменения в компоненте (`src/routes/council.tsx`)

- `NewCouncilPanel`: убрать шаг 2 (ручной выбор персон) из обязательного пути; `start()` вызывает `suggestPersonas` и создаёт сессию сразу после выбора кейса.
- `SessionView`: перейти на 3-колоночный grid; добавить панель вердикта справа, инициализированную `topic.insight` до первого follow-up; `send()` вызывает `buildVerdict` вместо статичной строки.
- Новый компонент `PersonaPicker` (или расширение существующей разметки в `NewCouncilPanel`) с полем поиска — переиспользуется и для «Изменить состав» в левой колонке сессии, и как fallback в создании сессии.

## Вне рамок этой спецификации

- Реальная генерация текста через LLM — синтез и реплики персон остаются детерминированными mock-функциями, как сегодня.
- Персистентность/бэкенд для сессий — не меняется (использует существующий `useCouncilSessions`).
