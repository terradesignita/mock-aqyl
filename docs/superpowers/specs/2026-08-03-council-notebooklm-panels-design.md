# Консилиум: панели в стиле открытого кейса (NotebookLM) — спецификация

Дата: 2026-08-03

## Проблема

Открытый кейс (`src/routes/card.$id.tsx` + `notebook/SourcesPanel.tsx` + `notebook/StudioPanel.tsx`) и Консилиум (`src/routes/council.tsx`) используют одну и ту же 3-колоночную идею (список слева / диалог в центре / вывод справа), но кейс выглядит заметно более «NotebookLM»: боковые панели сворачиваются и растягиваются мышкой, свёрнутую панель можно вернуть плавающей кнопкой-стрелкой, у панелей единый стиль заголовка со счётчиком. У Консилиума обе боковые колонки — статичная фиксированная ширина, без сворачивания.

Задача: перенести в Консилиум только этот визуальный/интерактивный язык панелей. Контент колонок и мобильное поведение не меняются.

## Решение

### 1. Левая панель — список сессий

Текущий `<aside>` в `CouncilPage` (`council.tsx`) получает заголовок в духе `SourcesPanel`:

```
«Сессии» + счётчик (today.length + earlier.length) + кнопка свернуть (PanelLeftClose)
```

Ниже заголовка — без изменений: кнопка «Создать совет», группы «Сегодня»/«Ранее», блок состава активного совета внизу.

- Ручка ресайза (drag) на правом крае панели, ширина зажата в 220–520px, дефолт 320px (как сейчас).
- Панель рендерится всегда — список сессий это первичная навигация, полностью прятать её нельзя.
- Сворачивание/ресайз активны только на `md:` и шире (см. §4).

### 2. Правая панель — вердикт

`VerdictPanel` получает заголовок в духе `StudioPanel`:

```
кнопка свернуть (PanelRightClose) + «Вердикт совета»
```

Содержимое (текст синтеза, открытые вопросы, теги согласия/риска) не меняется.

- Ручка ресайза на левом крае, ширина 220–480px, дефолт 260px (как сейчас).
- Панель рендерится только при активной сессии (`{active && <VerdictPanel />}`) — как сегодня.

### 3. Плавающие кнопки возврата

Когда панель свёрнута, у соответствующего края экрана появляется узкая кнопка-стрелка (`PanelLeft` / `PanelRight` из `lucide-react`), визуально идентичная той, что в `card.$id.tsx` (высота 16, ширина 6, скруглённый угол со стороны контента, тень, hover меняет цвет на `text-primary`).

- Видна только на `md:` и шире.
- Для левой панели: рендерится всегда, когда панель свёрнута (панель всегда доступна для разворачивания).
- Для правой панели: рендерится, только если есть активная сессия и панель свёрнута.

### 4. Брейкпоинты и мобильное поведение — без изменений

В отличие от кейса (там `Sources`/`Studio` полностью скрыты ниже `lg:`/`xl:`, доступен только чат), Консилиум **не** прячет колонки на мобильном — они складываются в столбик, как сегодня. Сворачивание/ресайз/плавающие кнопки — это новое поведение, которое имеет смысл только при боковом (не столбик) layout, поэтому активно с `md:` (768px), тем же брейкпоинтом, на котором `CouncilPage` уже переключается со столбика на строку.

### 5. Общий хук ресайза (мелкий рефактор существующего кода)

`card.$id.tsx` уже содержит рабочую логику drag-to-resize (`startResize`) для `Sources`/`Studio`. Вместо копирования её в третий и четвёртый раз в `council.tsx`, выношу в `src/hooks/useResizablePanel.ts`:

```ts
function clampWidth(value: number, min: number, max: number): number

function useResizablePanel(initial: number, opts: { min: number; max: number }): {
  width: number;
  startResize: (invert?: boolean) => (e: React.MouseEvent) => void;
}
```

- `startResize(invert)` — `invert: true` для панелей, растягиваемых от правого края (drag влево увеличивает ширину), как сегодняшний параметр `side === "right"` в `card.$id.tsx`.
- `card.$id.tsx` переключается на этот хук (два вызова — для `sourcesWidth`/`studioWidth`), `council.tsx` — тоже два вызова (для левой и правой панели). Поведение (курсор `col-resize`, `user-select: none` на время драга, снятие слушателей на `mouseup`) не меняется, только перестаёт дублироваться.

### 6. Новое состояние в `CouncilPage`

```ts
const [showSessions, setShowSessions] = useState(true);
const [showVerdict, setShowVerdict] = useState(true);
const { width: sessionsWidth, startResize: startSessionsResize } = useResizablePanel(320, { min: 220, max: 520 });
const { width: verdictWidth, startResize: startVerdictResize } = useResizablePanel(260, { min: 220, max: 480 });
```

Состояние не персистится (localStorage) — так же, как ширины панелей в `card.$id.tsx` сегодня: сбрасывается при перезагрузке/ремаунте.

## Изменения в файлах

- `src/hooks/useResizablePanel.ts` — новый хук + экспортируемая чистая функция `clampWidth`.
- `src/routes/card.$id.tsx` — `sourcesWidth`/`studioWidth` и их `startResize`-замыкания заменяются на `useResizablePanel`. Поведение не меняется, только источник логики.
- `src/routes/council.tsx` — заголовки `SessionRow`-списка и `VerdictPanel` получают панельный хедер (счётчик/кнопка свернуть), добавляются ручки ресайза, плавающие кнопки возврата, состояние collapse/width в `CouncilPage`.

## Тестирование

- `clampWidth` — чистая функция, 3 assert'а на границы (ниже min, выше max, в диапазоне) в `src/hooks/useResizablePanel.test.ts`.
- Остальное — ручная проверка через Playwright (открыть Консилиум, свернуть/развернуть/растянуть обе панели на desktop-ширине, проверить, что на mobile-ширине колонки складываются в столбик как раньше, прогнать существующий `vitest`-сьют и `tsc --noEmit`).

## Вне рамок этой спецификации

- Любые изменения контента панелей (что показывает список сессий, что показывает вердикт).
- Персистентность ширины/collapse-состояния панелей.
- Изменения мобильного поведения (остаётся столбик, не скрытие).
- Верхний хедер страницы (общий `Header`, не хедер конкретной сессии) — не трогаем.
