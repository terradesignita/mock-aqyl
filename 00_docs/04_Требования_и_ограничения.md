## Функциональные требования

### FR-1 Ingestion

Поддерживаемые форматы файлов (реализовано в `services/extraction.py`):

| Категория | Форматы |
|---|---|
| Документы | PDF, DOCX, PPTX, TXT, MD |
| Аудио | MP3, WAV, M4A, WEBM, OGG |
| Видео | MP4 (извлекается аудиодорожка для ASR) |
| Изображения | JPEG, PNG (OCR + VLM-описание) |

- Импорт из OneDrive-папок (FOLDER_SYNC коннектор) и ручной upload через Web UI/API.
- Идемпотентная обработка повторных загрузок (SHA-256 дедупликация + fuzzy-порог 0.94).
- Поддержка источников: MANUAL, FOLDER_SYNC, ONEDRIVE.
- Ограничение параллельной обработки: `INGESTION_MAX_CONCURRENT=3` (конфигурируется).

### FR-2 Processing

- OCR/извлечение текста для документов (PDF, DOCX, PPTX).
- ASR-транскрибация аудио и видео через OpenAI Whisper (`whisper-1`) или локальный Whisper fallback.
- Автоматическая нормализация метаданных (автор, дата, тип, язык, тема).
- Таймкодирование транскриптов: сохранение `TranscriptSegment` с `start_ms/end_ms` и диаризацией по спикерам.
- AI-суммаризация документа (`ai_summary`) после успешного индексирования.
- Автоматическая расстановка тегов (`tagging_status`) и маскирование чувствительных данных (`masked_text`).

### FR-3 Insight Cards (Артефакты)

- Генерация карточки инсайта по утвержденному шаблону (kind: `card`).
- Хранение версий карточек (`ArtifactVersion`) с поддержкой нескольких языков.
- Отображение цитат из источников (`ArtifactCitation` с chunk_id, quote, anchor, score).
- Поддержка типов артефактов: `card`, `summary`, `podcast`, `flashcard`, и другие (расширяемый enum).
- Экспорт артефактов через `/api/v1/artifacts/{id}/export`.

### FR-4 Q&A и Chat

- Вопросы в контексте конкретной карточки: `POST /api/v1/cards/{id}/ask`.
- Вопросы в контексте документа: `POST /api/v1/documents/{id}/ask`.
- Глобальный чат-режим: `POST /api/v1/chat`.
- AI-советник (advisor): `POST /api/v1/advisor/ask` для структурированных рекомендаций.

### FR-5 Коллекции (Topics)

- Организация документов в тематические коллекции (Topics).
- Иерархия коллекций (parent_id — вложенные темы).
- Роли участников коллекции: `owner`, `editor`, `viewer`.
- Привязка документов к нескольким коллекциям (M:N через `topic_documents`).
- Уведомления об активности в коллекции (`notifications`).

### FR-6 Студия артефактов (Studio)

- Генерация артефактов на основе документа или коллекции: `POST /api/v1/studio/generate`.
- Сравнение двух артефактов: `POST /api/v1/studio/compare`.
- Генерация обложек и иллюстраций через `/api/v1/images/generate` (DALL-E 3 или Imagen 3).
- Создание аудио-подкастов: `POST /api/v1/speech/podcast` и `POST /api/v1/speech/podcast/asset`.

### FR-7 Речевые функции (Speech/TTS/STT)

- Транскрибация аудио: `POST /api/v1/speech/transcribe`.
- Синтез речи (TTS): `POST /api/v1/speech/synthesize` (модель `gpt-4o-mini-tts`).
- Генерация подкастов с диалогом двух голосов (host/guest).
- Поддержка языков TTS: RU, EN, KK, UZ, AZ.

### FR-8 Мультиязычность

- Вход: определение языка источника (detect_language).
- Выход: RU / EN / KK / UZ / AZ.
- Сохранение терминологии в глоссарии (TermGlossary + TermTranslation).
- Мультиязычные поля тегов: `name_ru`, `name_en`, `name_kk`.
- Отложенный перевод артефактов: флаг `translation_pending`.

### FR-9 Поиск

- Гибридный поиск: семантический (векторный) + keyword (TSVECTOR/GIN).
- `GET /api/v1/search` и `POST /api/v1/search` с фильтрами по scope, language, business_unit.
- Опциональный LLM-реранкинг результатов (`ENABLE_LLM_RERANK`).

### FR-10 Доступы и аудит

- Режимы авторизации: `demo` (без SSO) и `sso` (корпоративный SSO).
- RBAC/ABAC: роли admin, editor, viewer; фильтрация по scope (INTERNAL/EXTERNAL) и business_unit.
- Классификация документов: PUBLIC, INTERNAL, CONFIDENTIAL, RESTRICTED.
- Логирование всех AI-запросов и действий в `query_logs` (AuditLog).
- Действия аудита: LOGIN, UPLOAD, FOLDER_SYNC, VIEW_CARD, SEARCH, ASK_CARD, ASK_DOCUMENT, ASK_GLOBAL, GENERATE_CARD, EXPORT, DELETE, UPDATE_GLOSSARY.

### FR-11 Skills и персонализация системного промпта

- Настраиваемые системные промпты по категориям: `mode` (expert, tutor...) и `position` (по должности).
- CRUD для Skills: `GET/PUT /api/v1/skills/{slug}`.

## Нефункциональные требования

- Производительность: P95 API <= 1.5 сек для поиска.
- Надежность: retriable jobs (3 попытки с exponential backoff) + dead-letter через PipelineJob.
- Масштабируемость: до 1000+ пользователей без смены архитектурного паттерна.
- Безопасность: шифрование, маскирование чувствительных данных, аудит.
- Наблюдаемость: метрики (`/api/v1/metrics`), структурированные логи (structlog), трассировки.
- Хранилище: локальное (default) или S3-совместимое (MinIO/AWS S3).
- Локали по умолчанию: `ru, en, kk, uz, az`.

## Ограничения

- Легальность хранения и отображения кейсов HBS требует отдельного юридического подтверждения.
- На старте источником хранения выступает OneDrive.
- Чувствительные данные не должны попадать во внешние LLM без маскирования (`MASK_EXTERNAL_LLM=true`).
- Максимальное параллельное ingestion: 3 воркера (конфигурируется через `INGESTION_MAX_CONCURRENT`).
- Аудио/видео файлы без ASR-транскрипта не могут быть проиндексированы семантически.
- Изображения обрабатываются через VLM (Vision Language Model), требуют настроенного Google Gateway или OpenAI.

## Допущения

- Корпоративный SSO и BILife API доступны для интеграции (в MVP режим `auth_mode=demo`).
- Есть утвержденные роли владельцев контента (Content Owners).
- Выбрана стратегия модельного роутинга (см. [[08_AI_модуль_RAG]]).
- База данных: PostgreSQL 16+ с расширением `pgvector` для хранения embeddings (768-мерные векторы).

## Критерии приемки MVP

```text
1) Загруженный документ (PDF/DOCX/PPTX/аудио) появляется в поиске <= 30 минут
2) Генерируется карточка с обязательными разделами и цитатами
3) Работают роли доступа минимум для 3 ролей (admin, editor, viewer)
4) RU/EN выдача доступна в UI; KK/UZ/AZ через флаг перевода
5) Аудит фиксирует все AI-запросы и ответы
6) Topics (коллекции) создаются и наполняются документами
7) Speech-синтез и транскрибация работают для WAV/MP3/OGG
```
