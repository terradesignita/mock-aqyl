# Безопасность и комплаенс

## Модель безопасности

- Zero Trust для сервис-сервис взаимодействий.
- Least Privilege для пользователей и сервис-аккаунтов.
- Security gates до обращения к LLM: PII masking выполняется в `backend/security.py` до передачи текста в AI-провайдер.

## Классификация данных

Реализована в `backend/models/enums.py` как `Classification(str, enum.Enum)`:

| Значение | Описание |
|---|---|
| `PUBLIC` | Открытые данные |
| `INTERNAL` | Внутренние корпоративные |
| `CONFIDENTIAL` | Конфиденциальные |
| `RESTRICTED` | Ограниченного доступа |

Классификация влияет на:
- доступность в поиске (`can_access_document` в `security.py`);
- возможность отправки во внешние LLM (`mask_external_llm` в `config.py`);
- требования к маскированию PII.

## Контроль доступа

### RBAC

Роли (`role`) определены в `backend/security.py`:

| Роль | Уровень |
|---|---:|
| `viewer` | 1 |
| `editor` | 2 |
| `owner` | 3 |
| `admin` | 4 |

- `viewer` — чтение карточек и поиск.
- `editor` — загрузка файлов (`can_upload`).
- `owner` — доступ к RESTRICTED в своём `business_unit`.
- `admin` — полный доступ, обход всех фильтров.

### ABAC

Атрибуты контекста (`UserContext` в `security.py`):
- `business_unit` — подразделение.
- `geo` — регион.
- `position` — должность (gd / pm / pto / legal / hr / finance / employee).
- `language` — предпочитаемый язык.

Логика `can_access_document`: RESTRICTED → требует `owner`+ и совпадение `business_unit`; INTERNAL scope → совпадение `business_unit`.

Логика `can_access_by_position`: документы с `access_layer != "open"` проверяют список `allowed_positions` (JSONB).

### Пример policy

```rego
allow {
  input.user.role == "viewer"
  input.resource.classification != "restricted"
  input.user.business_unit == input.resource.business_unit
}
```

## Режим аутентификации

Управляется параметром `AUTH_MODE` в `config.py`:
- `demo` — любые credentials принимаются, роль берётся из `AUTH_DEMO_ROLE` (default: `admin`). Используется для MVP/разработки.
- Продакшн-auth (BILife SSO / JWT) — планируется, сейчас возвращает HTTP 501.

## Защита данных

- TLS in transit (nginx gateway).
- Шифрование at rest (MinIO + PostgreSQL volume).
- KMS-managed keys (план: production).
- Secret rotation через `.env` / Secret Manager.
- `MASK_EXTERNAL_LLM=true` (default) — включает замену PII до вызовов внешних LLM.

## PII/DLP

Реализовано в `backend/security.py`, функция `mask_sensitive_text`:

```python
PII_PATTERNS = [
    re.compile(r"\b[\w.%+-]+@[\w.-]+\.[A-Za-z]{2,}\b"),   # email
    re.compile(r"\+?\d[\d\-() ]{8,}\d"),                    # phone
    re.compile(r"\b\d{12,19}\b"),                           # card/IIN
    re.compile(r"\b[A-Z]{2}\d{6,}\b"),                      # passport
]
```

- Pre-LLM masking: ФИО, email, телефоны, ID, финансовые реквизиты, кастомные паттерны.
- Logging без утечки исходных чувствительных фрагментов.
- `masked_text` хранится в `document_versions` отдельно от `extracted_text`.

## Юридический контур

- Проверка лицензионных ограничений HBS-контента.
- EXTERNAL scope (HBS) обрабатывается **только через NotebookLM** — без локального индексирования, в соответствии с GDPR и лицензией HBS.
- Разделение прав на full-text и derivative artifacts (insight cards).
- Политика удаления по legal request (`AuditAction.DELETE` в audit log).

## Аудит

Таблица `query_logs` в PostgreSQL. Логируются:

| Действие | Описание |
|---|---|
| `LOGIN` | Вход пользователя |
| `UPLOAD` | Загрузка файла |
| `FOLDER_SYNC` | Синхронизация папки |
| `VIEW_CARD` | Просмотр карточки |
| `SEARCH` | Поисковый запрос |
| `ASK_CARD` | Вопрос по карточке |
| `ASK_DOCUMENT` | Вопрос по документу |
| `ASK_GLOBAL` | Глобальный chat-вопрос |
| `GENERATE_CARD` | Генерация артефакта |
| `EXPORT` | Экспорт данных |
| `DELETE` | Удаление ресурса |
| `UPDATE_GLOSSARY` | Изменение глоссария |

Каждая запись содержит: `user_email`, `user_role`, `business_unit`, `geo`, `provider`, `model_name`, `request_json`, `response_preview`.
