## Поддержка

- L1: пользовательские вопросы и базовая диагностика (health endpoint, статус jobs).
- L2: сервисные сбои, интеграции (NotebookLM, Google Gateway), доступы.
- L3: инциденты данных/моделей/архитектуры (wiki lint failures, ingestion pipeline, LLM routing).

## Процесс изменения

1. RFC/ADR на значимое изменение (см. [[20_ADR_реестр]]).
2. Security review.
3. Stage validation.
4. Controlled rollout через feature flags (`ENABLE_WIKI_GENERATION`, `ENABLE_LLM_RERANK`, etc.).
5. Post-release monitoring 24 часа.

## Governance контента

- Каждая папка/домен имеет назначенного владельца (`owner_email` в таблице `topics`).
- SLA обновления карточек после поступления нового контента.
- Регулярный audit устаревших материалов (поле `updated_at` в `documents`, `topics`).
- EXTERNAL scope (HBS): контент только через NotebookLM, без локального хранения full-text.

## Операционные процессы AI-слоя

### LLM fallback chain
При недоступности основного провайдера (`ai_provider=auto` в config):
1. OpenAI GPT-4o-mini (основной).
2. Anthropic Claude Sonnet (`claude-sonnet-4-20250514`).
3. Google Gateway (Gemini 2.5 Pro через `GOOGLE_GATEWAY_URL`).
4. Ollama llama3.2:3b (локальный fallback, `OLLAMA_BASE_URL`).

### Wiki maintenance
- Wiki-страницы генерируются автоматически при ingest (до `WIKI_MAX_PAGES_PER_DOC=4` страниц).
- Lint-цикл каждые `WIKI_LINT_INTERVAL_HOURS=6` часов.
- Статусы: `pending` → `passing` / `issues`.
- Ответственный: Data/AI Team.

### Jobs monitoring
- Таблица `pipeline_jobs`: статусы `queued → running → completed / failed`.
- `RUN_INLINE_JOBS=true` (dev): jobs выполняются синхронно.
- `INGESTION_MAX_CONCURRENT=3`: параллельных потоков ingestion.
- Мониторинг: `GET /api/v1/jobs` (роутер jobs).
