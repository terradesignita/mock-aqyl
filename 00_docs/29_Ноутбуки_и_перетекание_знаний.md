# Ноутбуки и перетекание знаний (one-pager)

Навигация: [[02_О_чем_проект]] | [[03_Цели_и_KPI]] | [[28_Open_Issues]]

Версия: v0.1 (черновик после брейншторма 15.06.2026) | Статус: на обсуждение

## Проблема

Цель продукта — «повысить повторное использование корпоративных знаний». Но если личные
черновики пользователей навсегда остаются приватными, живой опыт оседает в личных блокнотах
и никуда не перетекает. Получается личный ассистент, а не платформа знаний.

Открытый вопрос из доков «Wiki — публичная или приватная?» решается здесь.

## Решение: три уровня знаний

Ложная развилка была «приватно навсегда» vs «влить в общую базу через аппрувера». Есть третий путь.

| Уровень | Кто пишет | Кто видит | Метка | Гейт |
|---|---|---|---|---|
| **Канон** | ingestion + редкий батч | все | проверено | агент номинирует, человек раз/нед |
| **Опыт коллег** | любой юзер, 1 клик | все | от коллеги, не проверено | нет |
| **Блокнот** | владелец | только он | черновик | нет |

- **Канон** — главная библиотека. Только чтение. Из интерфейса в неё писать нельзя → нет вандализма,
  конфликтов, RBAC.
- **Опыт коллег** — открытая полка. Любой публикует кейс из блокнота одним кликом, сразу, без проверки.
  На каждом — подпись автора и метка «не проверено».
- **Блокнот** — личный черновик пользователя (модель NotebookLM): докидывает файлы, задаёт вопросы.

## Жизненный цикл кейса

```
Блокнот (приватно)  ──«поделиться»──▶  Опыт коллег (видно всем, подпись + метка)
                                              │
                                   сигнал качества (доля «полезно» / просмотры)
                                              │
                                   Линтер раз/нед номинирует лучшее ▶ issue.md
                                              │
                                   человек батчем решает ▶ Канон (проверено)
```

Знание начинает перетекать в момент клика «поделиться» — без человека в цепочке. Промоушен в
канон — редкое батч-событие, а не очередь на каждого юзера. ФОТ не растёт.

## Доверие — на подписи и сигнале, не на гейте

Главный кейс не «кто-то проверил каждый», а:
- **подпись автора** («кейс от Петрова, Девелопмент») — для пилота из знакомых топов это сильнее «approved»;
- **метка уровня** — советник всегда помечает: проверено / от коллеги / черновик;
- **сигнал качества** — один явный («сохранить» ⭐ или «полезно» 👍) + **просмотры в фоне как знаменатель**.

Номинация в канон — по **доле** («полезно ÷ просмотры»), не по сырой сумме. Иначе наверх лезет
только старое и попсовое, а свежий хороший кейс не всплывает.

«Кинет херню» → канон не тронут, на херне его имя (социальная цена), советник пометит «не проверено».

## Советник (AI-Advisor)

- **Выключен** → лексический поиск (полнотекст, FTS5/Postgres FT). Детерминированно, мгновенно, ноль токенов.
- **Включён** → семантика. Ищет по всем уровням, источник каждого результата помечен.
- **Внутри блокнота** → по умолчанию ищет в библиотеке + блокноте, помечая источник. Без лишних галочек.
- **Ничего не нашёл** → честный refusal по умолчанию. Опционально отдельной кнопкой «общий взгляд из
  стратегии» — с цитатами и явной меткой «не из кейса». Не смешивать в одном пузыре
  (защищает KPI citation coverage ≥ 95%).

## Объём MVP

**В MVP:**
- Канон (read-only) + ingestion.
- Личные блокноты: файлы, Q&A, скоуп на блокнот.
- Полка «опыт коллег»: публикация в 1 клик, подпись, метка.
- Один сигнал качества + фоновые просмотры. Полка «свежее» против холодного старта.
- Советник on/off, метки источников, честный refusal.

**Потом (не MVP):**
- Авто-номинация Линтером в канон по доле + батч-триаж человеком.
- Сигналы-производные, рекомендации, расширенная аналитика перетекания.

**Сознательно НЕ делаем:**
- Формальные роли (аппрувер/ментор/суперадмин) — не нужны без пер-кейс гейта.
- Запись в канон из UI. Модерация/премодерация полки «опыт коллег».

## Зафиксированные решения (брейншторм 15–16.06.2026)

1. **Сигнал качества** — публичный «Полезно» 👍 (даёт social proof) + просмотры в фоне как знаменатель.
  Номинация в канон по доле «полезно ÷ просмотры», не по сумме.
2. **Видимость «опыт коллег»** — глобально + фильтр по BU (вариант 3). По умолчанию видят все подразделения;
  можно отфильтровать «только моё». Чувствительное прячем пометкой «конфиденциально» на документе,
  а не стеной по business_unit. Канон виден всем; блокнот — только владельцу.
3. **Scope при загрузке** — обычный пользователь scope не выбирает: его контент всегда `INTERNAL`.
  `EXTERNAL` (HBS через NotebookLM) — закрытый кураторский лейн админа, не галочка при загрузке.
  Scope ⊥ tier: External живёт только в каноне; пользователи производят только Internal.
4. **Совместность — асинхронная, не реалтайм.** Знание течёт через артефакты во времени, не через
  присутствие. Нет websockets/курсоров/блокировок/разрешения конфликтов (канон read-only,
  блокнот одно-владельческий). «Сессия» = идентичность per-request (email/role/BU/geo через SSO),
  не серверное коллаб-состояние.
5. **Уведомления** — главный кросс-юзер канал, pull/дайджест (не push-спам). Слать: «кейс продвинули
  в канон», «кейс отметили полезным N раз», опц. «новый кейс в твоей теме».

## Ещё открыто

- Минимальный порог просмотров N, прежде чем доля «полезно» учитывается в номинации (старт ≈ 20).
- Дедуп «опыт коллег» по эмбеддингу при публикации («похоже на существующий — дополнить?»).

## Что улучшить дальше (за рамками базовой модели)

По убыванию ценности.

1. **Отказ советника → петля пополнения.** «Ничего не нашёл» — самый ценный сигнал: спросили то,
  чего в базе нет. Логировать каждый refusal как «пробел в знаниях». Из этого: (а) бэклог «что
  ингестить следующим» пишется сам из реальных вопросов; (б) юзеру сразу — «по этому ещё нет кейса,
  хочешь создать?» → открывается блокнот. Отказ из тупика становится приглашением пополнить базу
  и связывает весь поток: вопрос без ответа → кейс → опыт коллег → канон. **Если делать одно — это.**
2. **Холодный старт как gate запуска.** На старте канон не лучше, чем ingestion из OneDrive. Тонкая
  база → советник отказывает постоянно → для Top-100 продукт выглядит мёртвым. Сделать «долю отказов»
  метрикой готовности: не запускать на Wave 1, пока refusal на тестовых вопросах выше ~30–40%.
3. **Авто-карточка при публикации.** Сырой блокнот ≠ хороший кейс; полка «опыт коллег» иначе станет
  свалкой. При «поделиться» — дешёвый LLM-проход собирает аккуратную карточку (заголовок, резюме,
  что сработало). «Идеальный кейс» становится авто-черновиком, а не ручной обязанностью.
4. **Мерять перетекание, а не MAU.** MAU обманет: люди ходят, знание силосится. Завести сразу:
  «доля ответов, цитирующих кейсы от пользователей (не ingestion)» и «время от блокнота до первого
  переиспользования другим человеком».
5. **Дедуп между уровнями.** Один урок в пяти блокнотах → пять карточек → шум. При публикации
  эмбеддинг-чек: «похоже на существующий кейс — дополнить или создать новый?».
