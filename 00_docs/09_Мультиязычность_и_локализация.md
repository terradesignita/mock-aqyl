## Поддерживаемые языки

Определены в `backend/config.py` через `DEFAULT_LOCALES`:

| Код | Язык |
|---|---|
| `ru` | Русский (default) |
| `en` | Английский |
| `kk` | Казахский |
| `uz` | Узбекский |
| `az` | Азербайджанский |

Константа `SUPPORTED_LANGUAGES: frozenset[str] = frozenset({"ru", "en", "kk", "uz", "az"})` объявлена в `backend/config.py`.

## Принцип работы

1. Определение языка источника — `langdetect` (библиотека в `pyproject.toml`).
2. Базовая генерация на языке источника.
3. Перевод в target-locales через `deep-translator` (библиотека в `pyproject.toml`).
4. Применение терминологического глоссария (`term_glossary` + `term_translations`).
5. QA-проверка консистентности.

## Локализационные сущности в БД

| Таблица | Назначение |
|---|---|
| `term_glossary` | Канонические термины (поле `canonical_term`) |
| `term_translations` | Перевод термина по языкам (`glossary_id`, `language`, `translated_term`) |
| `artifact_versions` | Отдельная версия артефакта (карточки) на каждом языке (`language`, `translation_pending`) |
| `wiki_pages` | Поле `language` — язык wiki-страницы |
| `documents` | Поле `title_i18n` (JSONB) — переводы заголовка документа |
| `tags` | Поля `name_en`, `name_kk`, `category_en`, `category_kk` — локализация тегов |

## Правила перевода

- Не переводить названия кейсов и имена собственные без правила в глоссарии.
- Сохранять исходные формулы и числовые параметры.
- Для управленческих терминов использовать корпоративные эквиваленты из `term_glossary`.

## Контроль качества

- Automated checks:
  - пропуски терминов (сверка с `term_translations`);
  - изменение чисел/дат;
  - недопустимые сокращения.
- Human review для high-impact карточек.
- Wiki-страницы: поле `lint_status` (pending / passing / issues), проверка каждые 6 часов.

## Fallback-логика

- Если перевод недоступен, API возвращает `source_language` + флаг `translation_pending=true`.
- В `ArtifactVersion`: поле `served_language` — фактически поданный язык, `translation_pending: bool`.

Пример статуса:

```json
{
  "card_id": "c-123",
  "requested_language": "kk",
  "served_language": "ru",
  "translation_pending": true
}
```

## Процесс ведения Translation Glossary (OI-010)

- Владелец: Localization Team / Product Owner.
- Новый термин добавляется через `POST /api/v1/glossary` (роль editor и выше).
- Перевод добавляется через `PUT /api/v1/glossary/{id}`.
- Обновление глоссария логируется в `query_logs` с действием `UPDATE_GLOSSARY`.
- Ревью обновлений — раз в спринт силами Localization Team.
