# BI AQYL — бизнес-контекст

Обзорный документ для тех, кто заходит в проект: что строим, для кого, зачем и по каким правилам.
Синтез из [[02_О_чем_проект]], [[03_Цели_и_KPI]] и решений брейншторма (см. [[29_Ноутбуки_и_перетекание_знаний]]).

Дата: 2026-06-16

## В одном абзаце

**BI AQYL** — корпоративная AI-платформа знаний BI Group. Сотрудник задаёт вопрос обычными словами
и получает ответ со ссылками на источники: из внутреннего опыта компании или из мировой библиотеки
кейсов. Цель — чтобы знания перестали лежать мёртвым грузом в файлах и начали переиспользоваться.

## Проблема

Сегодня знания компании разбросаны по файлам (`.pdf`, `.docx`, `.mp3`, `.png`) в структуре OneDrive.
Текущая HTML-витрина частично решает навигацию, но не закрывает:

- автоматическую загрузку и дедупликацию документов;
- единый поиск по смыслу, а не по имени файла;
- генерацию выжимок-инсайтов и диалог по содержимому;
- мультиязычную выдачу (RU/EN/KK/UZ/AZ);
- корпоративные требования к безопасности и масштабу.

Итог: ценный опыт есть, но найти и переиспользовать его трудно.

## Что строим

Платформа объединяет три источника знаний (модель уточнена на брейншторме):

| Уровень | Что это | Кто пишет | Доверие |
|---|---|---|---|
| **Канон** | Проверенная общая база | ingestion + редкий батч-апрув | проверено |
| **Опыт коллег** | Кейсы, которыми поделились пользователи | любой юзер, 1 клик | подпись автора + сигнал |
| **Личный блокнот** | Черновики пользователя | владелец | приватно |

Ключевая идея — **знание перетекает снизу вверх**: из личного блокнота в «опыт коллег» одним кликом,
а лучшие кейсы агент-линтер номинирует в канон. Без тяжёлой системы ролей и без роста штата.

## Паттерн «две кнопки»

Главная продуктовая развилка для пользователя:

- **Внутренний опыт BI** — поиск по Lessons Learned компании (scope `INTERNAL`, полный RAG).
- **Мировой опыт** — поиск по внешней библиотеке (кейсы HBS, scope `EXTERNAL`, через NotebookLM).

Это два независимых индекса с единым форматом ответа. Внешний scope использует NotebookLM вместо
локального индекса — из-за GDPR и лицензионных ограничений HBS.

## Для кого

Внедрение волнами:

- **Wave 1** — Top-100 руководителей.
- **Wave 2** — Top-500.
- **Wave 3** — массовый корпоративный доступ.

Важное следствие для дизайна: первые пользователи — занятые топ-менеджеры. Они задают вопрос и хотят
ответ, а не курируют личные базы. Интерфейс должен быть понятен «с порога».

## Цели

**Бизнес-цели:**
- сократить время поиска управленческих инсайтов;
- повысить повторное использование корпоративных знаний;
- ускорить внедрение лучших практик в работу.

**Технические цели:**
- отказоустойчивый конвейер загрузки и обработки;
- объяснимые ответы со ссылками на источники (citation coverage ≥ 95%);
- контроль стоимости LLM через маршрутизацию провайдеров (OpenAI → Anthropic → Google → Ollama);
- два режима: INTERNAL (полный RAG) и EXTERNAL (NotebookLM).

## KPI пилота (до 31 июля 2026)

| Метрика | Цель | Смысл |
|---|---:|---|
| Time-to-Card | ≤ 30 мин | от загрузки файла до готовой карточки инсайтов |
| Auto-processing rate | ≥ 85% | доля документов, обработанных без ручного вмешательства |
| Search helpfulness | ≥ 4.2/5 | средняя оценка полезности результатов |
| MAU (Top-100) | ≥ 60% | активные за 30 дней из 100 |
| Citation coverage | ≥ 95% | доля ответов со ссылками на источник |
| P95 API latency | ≤ 1.5 сек | скорость поиска |

**Анти-метрики** (чего избегаем): рост стоимости без роста пользы; рост доли ответов без цитат;
рост ручной обработки.

## Границы проекта

**В scope:**
- загрузка и обработка документов/аудио (pdf, docx, pptx, mp3, png);
- карточки инсайтов + Q&A по карточке;
- гибридный поиск (лексика + семантика);
- роли доступа (viewer/editor/owner/admin), ABAC по business_unit и geo, аудит;
- мультиязычность RU/EN/KK/UZ/AZ;
- авто-генерация wiki-страниц при загрузке;
- NotebookLM-коннектор (quiz, report, podcast, slides) для внешнего scope.

**Вне scope (1-я фаза):**
- сквозная автогенерация курсов LMS;
- полная замена корпоративного DMS;
- real-time синхронизация с >10 внешними источниками.

## Принципы, которые нельзя нарушать

1. **Не выдумывать.** Ответ — только из документов, со ссылками. Нет данных → честный отказ, а не
   галлюцинация. Это защищает citation coverage и доверие топ-менеджеров.
2. **Канон не пачкается.** В общую проверенную базу нельзя писать из интерфейса — только через
   ingestion и редкий апрув. Черновики и «опыт коллег» всегда помечены как непроверенные.
3. **Система работает сама.** Минимум ручного труда и без роста ФОТ — модерация через агентов
   (Линтер), человек только батч-решения по `issue.md`.

## Текущее техническое состояние (для разработчиков)

- **Frontend:** React 19 + Tailwind 4 + Zustand, i18n (5 языков), тёмная тема.
- **Backend:** FastAPI + Celery + Redis, конвейер ingestion, pgvector/Chroma для эмбеддингов.
- **Эмбеддинги:** всегда OpenAI (`text-embedding-3-small`), независимо от чат-провайдера —
  поэтому загрузка требует ключ OpenAI.
- **Ограничение:** нет OCR — сканированные PDF без текстового слоя пока не обрабатываются.
- Подробный разбор контрактов фронт↔бэк: см. [[AUDIT_API_CONTRACTS]] (в `03_audit/`).
