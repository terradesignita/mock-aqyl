## Назначение

Документация описывает:
- целевую архитектуру платформы;
- требования к ingestion/ETL, AI-аналитике, мультиязычности и безопасности;
- API-контракты, модель данных, DevOps/SRE-подход;
- план поставки от MVP до масштабирования;
- управленческий контур качества, риска и стоимости AI.

## Технический стек (актуально на 2026-04-20)

| Слой | Технология |
|---|---|
| Backend | FastAPI >= 0.116, Python 3.12–3.14, Uvicorn |
| ORM | SQLAlchemy >= 2.0, psycopg3 |
| База данных | PostgreSQL 17 (образ pgvector/pgvector:pg17), порт 5433 |
| Векторный индекс | pgvector 0.3+, HNSW (m=16, ef_construction=64), cosine similarity |
| Frontend | Vanilla JS SPA (собирается в nginx-контейнере) |
| Object Storage | MinIO (S3-compatible), порты 9000/9001 |
| Контейнеризация | Docker Compose (dev), docker-compose.prod.yml (prod) |
| AI провайдеры | OpenAI GPT-4o-mini (основной), Anthropic Claude Sonnet, Google Gateway (Gemini 2.5 Pro), Ollama llama3.2:3b (fallback) |
| NotebookLM | notebooklm-py CLI, notebook_id через `NOTEBOOKLM_NOTEBOOK_ID` |
| Embedding | text-embedding-3-small (OpenAI) / text-embedding-004 (Google) / hashing (fallback) |
| Chunking | 220 токенов / overlap 40 / rapidfuzz dedup threshold 0.94 |

## Принципы

- Source-first: ответы AI должны ссылаться на первоисточники.
- Security-by-design: маскирование PII и контроль доступа до вызовов LLM.
- Cost-aware: управление затратами LLM через маршрутизацию и кеш.
- Evolvable architecture: модульность и масштабирование без переписывания ядра.
- Wiki-first knowledge: Karpathy LLM wiki layer генерируется при ingest, обновляется каждые 6 часов через WikiLintJob.
