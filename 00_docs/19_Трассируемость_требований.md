## Матрица NFR -> Контроль

| NFR | Цель | Механизм | Проверка |
|---|---|---|---|
| Performance | P95 search <= 1.5s | HNSW индекс + hybrid search + `MIN_RELEVANCE_SCORE=0.35` | load/perf tests |
| Reliability | 99.5% availability | retriable queues + DR (RPO<=24h, RTO<=4h) | chaos drill + SLO checks |
| Security | Zero critical PII leaks | PII masking + `MASK_EXTERNAL_LLM=true` + policy guard | `test_position_access.py` + security audits |
| Scalability | 500+ users (Wave 2) | Stateless API + horizontal scaling + `INGESTION_MAX_CONCURRENT=3` | load tests wave2/wave3 |
| Data Quality | Dedup rate, chunk quality | rapidfuzz 0.94 + chunk 220/40 | `test_repositories.py` |
| Cost control | Cost-per-user не растёт >20% QoQ | LLM routing chain + token caps | [[26_FinOps_для_LLM]] |

## Процесс актуализации

1. При изменении FR/NFR обновлять эту матрицу в том же PR.
2. Для архитектурных изменений добавлять ADR в [[20_ADR_реестр]].
3. Перед релизом сверять матрицу с чеклистом [[14_Тестирование_и_качество]].
4. При добавлении нового роутера добавлять строку в матрицу FR.
